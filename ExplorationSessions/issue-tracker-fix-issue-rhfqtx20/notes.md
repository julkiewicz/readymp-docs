## Onboarding findings (2026-11-25)

- This checkout is the **docs site** (julkiewicz/readymp-docs). The code that raises the events lives in
  `readym-gameserver` (and its `readym-core-sdk` submodule), which this attempt cannot push to.
- 2026-11-25-discovery-keep-empty-scopes-always-on: read-only check of an existing readym-gameserver checkout on this
  machine (/state/repos/2026-11-08-smoke-game-sessions-pod/readym-gameserver, bf00af27, 2026-11-05):
  - `ServerState.ShouldKeepScopeWhenEmpty` returns true whenever `_keepEmptyScopes` is set; `OnAreaDeleted`
    (ServerState.cs:435-438) and `OnCellDeleted` (ServerState.cs:503-509) only fire when it returns false.
  - `OblivionConfigurationExtensions.cs:64` sets `ScopeRetentionOptions.KeepEmptyScopes = true` with no condition.
  - So on an OblivionMP server both events can never fire. This matches the issue and the triage.
  - `ReadyM.SDK.Server.Events.IServerEvents` (readym-core-sdk) declares them, with the comment "unless the server keeps
    it while empty". `ServerEventForwarder` passes them on to mods.
- Docs already say so: oblivion-mp/docs/Modding/Game/server-events.md (current) and the 1.0 versioned copy both say
  "An OblivionMP server keeps every area/cell, so this does not fire today" (added in eb8b51e, 2026-10-15). The
  reporter quotes the guide, so the docs part of the expected outcome was already met when they reported it.
- 2026-11-25-discovery-api-ref-is-generated: oblivion-mp/api-reference is generated by
  scripts/docfx-oblivion/generate-docs.ps1 from the SDK's XML doc comments, and the next regeneration overwrites it.
  Hand edits in history (8b78300, b1ee94c) only followed SDK changes. An [Obsolete] marker or a better summary has to
  come from readym-core-sdk.
